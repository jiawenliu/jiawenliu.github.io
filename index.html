  • ArchRoute-JIT — 鲲鹏微架构感知的算子路由与 JIT-BRGEMM 特化选择：将算子选择从「矩阵形状 + dtype」静态查表升级为「指令集能力 + NUMA 亲和 + Cache 层级」的运行时微架构感知路由，使 INT8 GEMM 自动落到支持 i8mm 的鲲鹏 920B/950 特化内核，避免 ONNX Runtime 在 ARM 上回退到非 ACL 的 CPUExecutionProvider 低效路径。

  • CompileLocal-NUMA — NUMA-Local 预编译产物亲和缓存与启动期微基准快速搜索（详见项目三）。

项目背景

CPU 图编译加速（重点开发项目）

重点开发负责人 · 主导 CompileLocal-NUMA 体系从方案设计、代码实现到交付落地
📅 2026.06 – Now · 职级 20/19 · ICT-公共开发部-推理加速业务组
NEW · 重点开发
  • 预编译产物 NUMA-local 分配：通过 mbind / numa_alloc_local 将融合算子二进制、常量折叠权重布局、slot mapping 模板等预编译产物（数十 MB～数百 MB）常驻分配在 worker 绑定的本地 NUMA 节点/大页并生命周期内不迁移，消除首次 forward 的跨节点加载（远端带宽约本地 1/3、延迟 2–3 倍）。
  • JIT 缓存按 NUMA 节点分片：将 KDNN JIT 缓存目录从全局单例改为 CACHE_ROOT/numa_N/ 分片，各 NUMA 进程/DP rank 只读写本地分片并按节点独立淘汰，消除高核数下多进程并发编译的文件锁/内存锁竞争。
  • 启动期「快速搜索」替代黑盒 autotuning：仅对典型 shape 桶（prefill [1k, 4k, 8k, 16k]、decode [1, 2, 4, 8, 16, 32]）做一次性微基准标定生成决策表，非典型 shape 由 JIT 按需生成并缓存，将启动期搜索空间从「全 shape」压缩到「桶边界 shape」。
  • 图产物 NUMA-local 预取：服务进入就绪前通过 madvise(MADV_WILLNEED) / 访问预热 prefault 预编译产物到本地，消除首次 forward 触发的 demand paging 与跨节点加载长尾。
  • V4 Hash-MoE 常量折叠联动：将 V4 前 3 层冻结路由在图中完全常量折叠，消除 3/43 层路由相关的 JIT/autotuning 开销；针对 Grouped Output Projection 的分组低秩形状，按组大小分布设计 shape 桶。
成果（预估）：冷启动到就绪时间预计缩短 15–30%；启动期图编译/搜索阶段绝对时间预计压缩 20–40%（基于微架构比例的定性估计，通过启动时间分解 profile 收敛）。交付件：NUMA-local 预编译分配 patch、KDNN JIT 缓存分片 patch、桶边界标定脚本与决策表、启动时间分解 profile 报告、V4 Hash-MoE 常量折叠融合 pass。
项目背景

图预编译产物若被分配在远端 NUMA 节点、或 JIT 缓存被多 NUMA 进程全局争用，服务热起来后的首次 forward 会反复触发跨节点加载与缓存锁竞争，「一次性开销」形成长尾：冷启动时间被拉长的同时热路径首次访问也受污染。鲲鹏+昇腾场景图编译与算子融合阶段约 80 秒（Dynamo 20s + CANN 48s + warm-up），整个启动链 4–5 分钟，弹性扩缩容时该长尾直接影响新实例就绪时间。

03

CPU Graph Compilation Acceleration (Key Development)

Lead developer of the CPU graph compilation acceleration (CompileLocal-NUMA) from design and implementation to delivery.
📅 2026.06 – Now · Level 20/19 · ICT-Public Development Dept., Inference Acceleration Group
KEY
  • NUMA-local allocation of precompiled artifacts: uses mbind / numa_alloc_local to pin fused-operator binaries, constant-folded weight layouts, and slot-mapping templates (tens to hundreds of MB) to the worker-bound local NUMA node / huge pages for their lifetime, eliminating cross-node loading on first forward (remote bandwidth ≈ 1/3 of local, latency 2–3×).
  • NUMA-sharded JIT caches: changes the KDNN JIT cache from a global singleton to per-node CACHE_ROOT/numa_N/ shards, so each NUMA process / DP rank reads and writes only its local shard with independent eviction, removing lock contention among concurrent compilers on high-core-count systems.
  • Startup "fast search" instead of black-box autotuning: calibrates only typical shape buckets once at startup (prefill [1k, 4k, 8k, 16k]; decode [1, 2, 4, 8, 16, 32]) to build a decision table; non-typical shapes are JIT-generated on demand and cached, compressing the startup search space from all shapes to bucket boundaries.
  • NUMA-local prefetch of graph artifacts: prefaults precompiled artifacts into local memory (madvise(MADV_WILLNEED) / access warming) before readiness, eliminating demand paging and cross-node loading on the first forward.
  • V4 Hash-MoE constant folding: fully constant-folds the first 3 frozen routing layers of V4, removing their runtime routing decisions and JIT/autotuning needs (3/43 layers), and sizes shape buckets by the group-size distribution of Grouped Output Projection.
Outcomes (estimated): cold-start-to-ready time expected to drop 15–30%; startup graph compilation/search time expected to compress 20–40% (qualitative estimates based on microarchitectural ratios). Deliverables: NUMA-local allocation patch, JIT cache sharding patch, bucket-boundary calibration script + decision tables, startup time-breakdown profiling report, and a V4 Hash-MoE constant-folding fusion pass.
